# Virtual Ecosystem array variables

The table below list all of the variables that are stored centrally within Virtual
Ecosystem simulations. These variables are arrays of data that are structured using the
[core axes of the simulation](../../using_the_ve/axes.md).

Each science model declares which of these variables are used when the model runs. There
are five different usage cases, identifying sets of variables that are:

* required when the model is set up: either provided as input data or
  populated by another model.
* populated when the model is set up, and then available for other
  models.
* required when the model updates,
* populated when the model first updates, and
* updated by the model at every time step.

The buttons below can be used to filter the list of variables to particular models and
usage cases. The dropdown buttons at the start of each row reveal more details for each
variable.

```{warning}
The filter option for variables required to setup or update specific models includes
variables that are generated by other models (as part of their setup or update
processes). As a user what you need to know is the "absolute" requirements, i.e. the
variables that must be provided in the input data for the model to setup and update
successfully. While this can be found using the table below, unfortunately doing so is
quite a finicky process.
```

```{note}
Whether a variable is required by a specific model is determined solely by whether the
model uses it. There is generally a good match between the model that requires a
variable and the type of data that is required, e.g. the animal model mostly requires
animal data. However, this matching is not perfect and so variables required for a
specific model might be better gathered as part of another models gathering process. For
example, when setting up the animal model you must provide initial sizes of various
resource pools many of which come from other models (e.g. fungal fruiting bodies and the
soil model). While these are listed as animal model input requirements it probably makes
significantly more sense for them to be gathered as part of the data gathering process
for the model they come from.
```
